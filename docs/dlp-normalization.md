# DLP 归一化管线（F29）

DLP 检测原来只在原文上做一次匹配。敏感内容稍加变形就能绕过：
词中间插空格（`机 密`）、插零宽字符（`机\u200b密`）、换全角
（`ＸＨ－２００`）、换大小写（`SeCrEt`）、手机号拆成
`138-0000-0000`。本管线在检测前对文本做归一化，让变形后的内容
仍能命中词表与规则。

借鉴 1Panel AI 网关的内容合规做法（飞致云论坛与官方博客，
2026-11-22 查阅）：「动态敏感词拦截：支持自定义行业词库和黑白
名单，并且通过归一化处理识别谐音、拆字、拼音等变形内容」。我们
只借其归一化管线的形态（检测前归一化、只用于判定、不改写原文），
1Panel 为闭源商业产品，不复制代码；实现全部自研、纯标准库。

## 两个归一化视图

词表与正则对标点的要求不同，所以归一化产出两个视图：

| 视图 | 做法 | 用途 |
| --- | --- | --- |
| 关键词视图（`normalize.Keywords`） | 全角→半角、统一小写、只保留字母与数字（空白、分隔符、零宽字符全部去掉） | 违禁词 / 企业自定义词匹配：`XH-200` 须命中 `XH 200`、`ＸＨ－２００`、`X\u200bH-200` |
| 模式视图（`normalize.Patterns`） | 全角→半角、统一小写、去掉空白与不可见字符，保留标点 | 正则匹配：API Key 模式要留着 `-`（`ｓｋ-…` 折叠后仍命中）、邮箱模式要留着 `@` 与 `.`（`ａ＠ｂ．ｃｏｍ` 折叠后仍命中） |

两个视图都去掉的：全角字符（含全角空格 U+3000）、大小写差异、
零宽字符（U+200B/U+200C/U+200D、U+FEFF、U+2060、U+180E、
U+00AD）与 Unicode 格式类（Cf，如方向控制符）。

## 检测流程

`guard.Detector.Scan` 现在做三遍，取并集：

1. **原文直扫**（与原来完全一致）：词表 + 内置正则。
2. **关键词视图**：归一化后的词表（构造时同样归一化）+ 内置
   正则。手机号被 `-` 拆开时在这里命中。
3. **模式视图**：内置正则。全角凭据与邮箱在这里命中。

每遍的命中都通过 `normalize.Normalized` 的回指表映射回原文
字节偏移，`Finding.Value` 恒为原文片段（含插进来的分隔符）。
脱敏时整个原文片段被占位符替换，响应还原时原样返回——上游只
见占位符，下游看到的仍是用户原样输入。

## 红线：只增命中、不减命中

- 原文直扫一字不动：它命中的发现原样保留，归一化发现与之重叠
  时直接丢弃（也避免两处发现重叠导致 `Redactor` 按偏移替换时
  损坏文本）。
- 归一化只用于匹配判定：转发的请求正文、审计记录、告警内容均
  保持原样；审计 `detail.findings` 只记 `类别:种类`，不记匹配
  文本（变形文本同样不记）。
- 归一化不产生新的敏感原文落盘：映射表只在本次 `Scan` 调用的
  内存中。

## 顺带修的一个旧缺陷

内置 `password_assignment` 正则原来写的是
`\b(?:password|passwd|pwd|密码)`。Go 的 `\b` 只认 ASCII 词边界，
汉字不是词字符，所以行首或中文标点后的 `密码：…` 永远匹配不上。
本轮改为只对 ASCII 候选词要求词边界：
`(?:\b(?:password|passwd|pwd)|密码)`。这是同一条目的检测缺口，
不是 F29 之外的行为变更。

## 已知限制

- **谐音 / 拼音 / 拆字识别不在本轮**：需要拼音词典与拆字表，
  工程量大，按 Nathan 2026-11-22 的决定后续单独评估。当前
  管线是标准库可及的 80%（全角、大小写、分隔符、零宽字符）。
- **兼容字符不折叠**：`①`、`²` 这类兼容字符需要 NFKC（`x/text`
  依赖），本轮不做；非常用变形手段。
- **归一化可能多命中**：两个本来分开的词被分隔符连起来时，
  若恰好拼成一个违禁词也会命中（如 `sec. ret` 拼成 `secret`）。
  这是变形检测的固有代价，且网关对误拦的处置是明确的 400，
  管理员可在词表里收紧。只增不减的红线不受影响。
- **性能**：`Scan` 现在最多跑三遍匹配（原文 + 两个视图）。
  检测对象是聊天消息与工具参数，量级很小；空词表的自动机匹配
  立即返回，不产生额外开销。
- 归一化不改变分级、路由、缓存与计费：命中类别与密级与原来
  的同种发现一致，缓存键仍按原文计算。
