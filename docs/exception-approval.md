# 高密级调用例外审批流（F24）

被分级策略拦截的调用，员工可申请例外、管理员审批、凭一次性放行凭证
放行该次调用。流程借鉴 IP-guard 类产品的外发解密审批工作流（申请 →
审批 → 本次放行 → 全程留痕）：审批通过对应的是本次申请和本次调用，
不等于此后可随意调用；后续再次调用仍须重新申请。

## 流程

1. **申请**：员工在管理台「例外审批」页或 `POST /api/exceptions` 提交
   申请：数据密级（机密/绝密）、理由、调用范围（模型/任务）、有效期
   （1–72 小时）。仅机密及以上需要例外；公开/内部调用本来就不会被
   分级策略拦截，申请会被拒绝。
2. **审批**：管理员（admin/security）在管理台审批。批准时签发一次性
   放行凭证，驳回时可附理由；已批准未使用的凭证可由管理员撤销。
3. **放行**：申请人把凭证以 `X-AgentGate-Exception-Grant` 请求头带在
   被拦截的调用上；网关核验后放行该次调用，随即作废凭证。
4. **留痕**：申请、批准、驳回、撤销、凭证使用全程进审计；申请与批准
   触发 Webhook 告警（F5），以便管理员及时处理待审批事项。

## 凭证的绑定与一次性

凭证是一段随机 token（`exc_` + 48 位十六进制），服务端只存其 SHA-256
哈希，原文仅在批准响应里返回一次，此后任何接口都不再返回。网关核验
时绑定四项，缺一不可：

- 凭证哈希与记录一致；
- 申请人与持令牌的用户是同一人（别人的凭证不能用）；
- 凭证密级覆盖本次调用的密级（机密凭证放不了绝密调用）；
- 未过期、未使用、未撤销。

消费发生在网关确认放行该次调用之时（选路完成、即将转发），并在存储
锁内二次校验：两个并发请求携带同一凭证时，只有一个能消费，另一个
以 `exception_grant_invalid` 被拦。凭证只在真正需要豁免时才消费：
合规路由本来就能走的调用不会烧掉凭证；违禁词拦截永不例外，带凭证
的违禁调用仍被拦截、凭证也不作废。

## 豁免范围与红线

凭证只豁免两处分级拦截：

- **自带级禁发机密以上数据**（`data_level_forbidden`）：凭证放行后，
  调用仍按信任梯度选路——走签约云时网关照常强制脱敏，云端只见占位符。
- **无合规通道**（`no_compliant_channel`）：如绝密调用且无本地模型
  渠道，凭证允许本次走密级足够的最低信任渠道（如专有云/VPC），原文
  按该渠道的信任类型处理。

以下永不豁免：

- **违禁词拦截**：违禁内容不设例外。
- **绝密例外默认关闭**：须运维显式设置
  `AGENTGATE_ALLOW_TOPSECRET_EXCEPTIONS=1` 才允许申请绝密例外；
  未开启时申请直接 400。已批的绝密凭证可在开关关闭后由管理员撤销。
- **限流、部门预算、配额**：凭证只豁免分级拦截，不豁免其他控制。

放行不改变分级策略本身：凭证用完即作废，策略、渠道信任类型与默认
拦截行为原封不动；下一次同类调用仍须重新申请。

## API

| 方法 | 路径 | 权限 | 说明 |
| ---- | ---- | ---- | ---- |
| POST | `/api/exceptions` | 任意登录用户 | 申请；`{data_level, reason, scope, hours}` |
| GET | `/api/exceptions` | 登录用户（管理员看全部，员工只看自己的） | `?status=` 筛选 |
| GET | `/api/exceptions/{id}` | 申请人或管理员 | 详情（永不含凭证） |
| POST | `/api/exceptions/{id}/approve` | 管理员 | 批准；响应含 `grant`（仅此一次） |
| POST | `/api/exceptions/{id}/reject` | 管理员 | 驳回 |
| POST | `/api/exceptions/{id}/revoke` | 管理员 | 撤销已批准未使用的凭证 |

状态：`pending` → `approved` → `used`；`pending` → `rejected`；
`approved` → `revoked`；过期的 `approved` 在读取时 lazily 置为
`expired`。

## 审计与告警

审计事件 Kind 均为 `exception`，Detail 只含元数据（例外 ID、密级、
申请人、有效期小时数），**不含理由与范围原文**（申请理由本身可能
描述敏感工作，不进审计）：

- `exception_requested` / `exception_approved` / `exception_rejected` /
  `exception_revoked`（管理 API 记）
- `exception_grant_used`（网关记，含 `exception_id`；被放行的
  `model_call` 事件 Detail 同样带 `exception_id`，可双向追溯）
- 凭证无效的拦截记 `violation` / `model_call_blocked`，原因
  `exception_grant_invalid`

`exception_requested` 与 `exception_approved` 触发 Webhook 告警
（warning）；凭证使用是正常操作，不告警。

## 边界

- `scope` 是给审批人看的说明文字，网关不做机器匹配：网关强制的
  绑定是申请人 + 密级 + 有效期 + 一次性。
- 凭证在网关确认转发时消费：转发后上游故障（502）不退还凭证，
  须重新申请。
- 凭证哈希与申请记录随平台快照持久化，重启后仍有效（未过期的话）；
  服务端不存凭证原文，丢了就只能重新申请。
