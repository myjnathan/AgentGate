# 合规周期报表（F25）

面向等保 / 保密评审的周期报表：按周 / 月生成，管理台可预览、导出 CSV
表格。报表只含统计与元数据，不含敏感原文。

## 报表是什么

一份报表是一份**冻结的快照**：周期窗口内的审计事件聚合 + 生成时刻的
平台状态（渠道健康、令牌与终端概况）。同一周期可重复生成，每次生成
都是独立的一份；生成后数字不再变化，事后审计事件的归档（F4）也不会
改写已生成的报表。

## 周期

- 周报表：周一 00:00（UTC）至下周一 00:00（ISO 周）。
- 月报表：自然月 1 日 00:00（UTC）至下月 1 日。
- 生成时传 `period`（weekly | monthly）与可选 `date`（YYYY-MM-DD，缺省
  为今天 UTC）；`date` 只决定落在哪个周期，不决定窗口边界。

## 报表内容

| 节 | 内容 | 来源 |
|---|---|---|
| 用量总计 | 调用数、Token、拦截数、成本（USD）、未定价调用数、已脱敏调用数、DryRun 观察调用数 | 审计日志（与 F2 用量统计同一口径：model_call 事件 + violation/model_call_blocked） |
| 分组 | 按部门 / 渠道 / 模型 / 数据密级 / 处置分组的调用、Token、拦截、成本 | 同上 |
| 拦截原因 | 拦截按原因分组（策略原因如 no_compliant_channel、department_budget_exceeded；DLP 拦截按首个发现类别，如 banned_word）与按发现类别分组 | 同上；原因与类别只含类别名，不含原文 |
| Top 风险事件 | 最频繁的风险形态（前 8）：拦截、账号锁定、预算告警、限流 | 审计事件 kind/action 分组，原因是组内最常见的那一个 |
| 渠道健康 | 渠道总数、健康 / 熔断冷却 / 停用数，逐渠道健康与连续失败数 | 生成时刻快照 |
| 令牌概况 | 令牌总数、受管级 / 自带级、已证明、已吊销、已过期 | 生成时刻快照 |
| 终端概况 | 终端总数、在线 / 陈旧 / 离线、漂移数 | 生成时刻快照（F23 终端清单） |
| 例外审批 | 周期内申请 / 批准 / 驳回 / 撤销 / 凭证使用数 | 审计事件（F24） |
| 审计范围 | 窗口内事件数、生成时哈希链是否完整 | 审计日志 |

每份报表都带一句说明：「本报表仅含统计与元数据，不含敏感原文；报表是
审计证据，不是合规认证。」——借鉴 Wazuh 合规仪表盘的做法（规则映射到
PCI DSS / HIPAA / GDPR / NIST 800-53 等框架、供审计师取证），映射与统计
帮助审计师找到事实，是否合规由审计师判定，报表本身不下结论。

## 接口

- `POST /api/reports`：生成。Body：`{"period": "weekly"|"monthly", "date": "2026-11-16"?}`。201 返回整份报表。
- `GET /api/reports`：列表（摘要：周期、生成时间/人、调用/Token/拦截），按生成时间倒序。
- `GET /api/reports/{id}`：预览整份报表。
- `GET /api/reports/{id}/export`：下载 CSV（`agentgate-report-<id>.csv`），扁平表：`section,key,calls,tokens,blocked,cost_usd`。
- `DELETE /api/reports/{id}`：删除。

全部仅 admin / security。生成、导出、删除本身记审计（只含报表 ID 与周期）。

## 保留

最多保留 52 份报表（一年周报量），生成第 53 份时删除最旧的一份。

## 红线

- 报表不含任何敏感原文：不含请求/响应文本、不含 DLP 命中值、不含理由与
  范围原文（F24 的申请理由同样不进报表）；拦截只按原因类别与发现类别
  计数；Top 风险事件只含 kind/action/原因类别；被拦截最多的用户只列用户
  名与次数。
- 报表数字与审计日志对账：用量口径与 F2 `/api/stats` 完全一致，同一窗口
  的数字应当相等；成本为 0 的调用单独计为未定价（F13 同款保守口径）。
- 报表不是合规结论：不给任何框架的「通过/不通过」，不做控制映射打分；
  框架映射（等保条款对照）留待后续轮次评估。
