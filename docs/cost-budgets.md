# 成本计价与部门预算（F13）

模型调用花了多少钱、哪个部门花的、超了没有——这是企业上网关后财务第
一个要问的问题。本功能分两件：**计价**（每次调用按单价折算成美元，记进
审计、汇总进统计）与**部门月度预算**（硬上限，超了就拦）。

借鉴：LiteLLM 的虚拟 key 预算（`max_budget` + `budget_duration`，超限后
下一调用直接拒绝）与 Portkey 的预算上限（按 key/工作区设 USD 或 token
上限、80% 式告警阈值、每月 1 日 0 点 UTC 重置）。我们的差异：预算按部门
（不是按 key）设——企业是按部门分钱的；计价的单价配在渠道上（同一模型
从不同供应商买、价格可以不同）。

## 计价

- 渠道可为每个模型配单价：`pricing: {"mock-pro": {"input_per_million": 2.5, "output_per_million": 10}}`，
  单位是 **USD / 每百万 token**，输入与输出分开计（LiteLLM 的成本表同款
  形状：`input_cost_per_token` / `output_cost_per_token`）。
- 调用完成后按上游实际返回的 usage 拆分计价：
  `cost = prompt_tokens / 1e6 × input价 + completion_tokens / 1e6 × output价`，
  流式调用同样计价（usage 在流尾提取）。
- 成本在调用时**写进审计事件**（`cost_usd` 字段，随哈希链一起存），此后
  单价再改也不会改写历史——统计与审计永远对得上（F2 的对账原则）。
- 没有配单价的模型照常服务，成本记 0；统计里这类调用单独计为
  `unpriced_calls`，成本总数因此永远是**下限**，不是编出来的总数。
  本地小模型渠道单价为 0（没有上游按量账单），在统计中同样计入
  `unpriced_calls`：0 价与未定价在事件里无法区分，这是有意的保守口径。

## 部门月度预算

- 管理 API：`GET /api/budgets`（列表，含本月已花/剩余/已用比例）、
  `POST /api/budgets`（新建：部门 + 月度上限 USD + 可选告警阈值 0–1）、
  `PATCH /api/budgets/{id}`（改上限或阈值）、`DELETE /api/budgets/{id}`。
  每个部门最多一个预算；仅 admin 可操作。
- 月份是**自然月（UTC）**，每月 1 日 0 点自动重置（Portkey 的月度重置
  口径）；上限是硬上限——部门本月花费达到上限后，网关在流水线之前就以
  `429 department_budget_exceeded` 拒绝后续模型调用，并记一条
  `violation` 审计事件（统计里计为一次拦截、F5 告警为 critical）。
  正在途中的调用永远不会被中途拦下（LiteLLM 的“下一调用才拒绝”规则）。
- 告警阈值（如 0.8）是 Portkey 式的提前提醒：本月花费首次达到阈值的
  80% 时记一条 `budget_threshold` 审计事件（每月每部门只记一次），
  经 F5 告警通道以 warning 发出；不设阈值（0）则不提醒。
- 花费取自审计日志中本月 `model_call` 事件的 `cost_usd` 之和——被拦截的
  调用、缓存命中、管理操作都不花上游的钱，一律不计。

## 管理台

- 用量统计页：按部门/模型/渠道三张表各加「成本 (USD)」列；总览 KPI 下
  显示累计成本与未定价调用数。
- 用量统计页新增「部门月度预算」卡片：列表（上限、本月已花、剩余、已用
  比例与阈值）、新建、行内改上限、删除。
- 渠道表新增「单价」列（`输入价/输出价`）；添加渠道表单可填单价 JSON。

## 已知限制

- 预算按审计日志实时汇总：重启后审计日志重读，花费不丢失；但审计归档
  （F4）把事件移出热日志后，归档段的花费不再计入当月预算——归档只应
  对已过保留期的旧事件做，默认 180 天，不会动当月数据。
- 成本是调用完成时才知道的精确数：一次调用本身可能把花费推过上限，
  拦的是下一次调用，不会中途掐断已发出的请求。
- 单价是管理员手工配置的静态价：上游调价后需要管理员同步改单价；实时
  拉取厂商价目表不在本轮范围。
