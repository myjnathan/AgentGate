# 复杂度智能路由（F30）

客户端请求 `model=auto` 时，网关按请求复杂度在简单（便宜）与复杂
（强）两个模型组之间选路：简单请求走便宜模型组、复杂请求走强模型组。
复杂度只决定在同一密级与信任梯度内选哪个模型组，**不改变分级约束**——
分级路由（F17）永远优先，复杂度路由只在合规渠道集合内做成本优化。

## 设计来源

- **1Panel AI 网关**（飞致云官方文档 1panel.pro/docs/v2/user_manual/ai/gateway，
  2026-11-23 查阅）：智能路由只在客户端请求 `model=auto` 时触发，其他模型
  名走正常转发流程；先配简单与复杂两个模型组（组内模型顺序即选路优先级，
  组内不做负载均衡），再在「设置 → Embedding」配向量服务、路由阈值与 TopK，
  在「智能路由 → 样本」维护简单 / 复杂请求样本并生成向量；网关把请求转成语义
  向量、与预置的简单 / 复杂样本算相似度，样本无法明确命中时再通过规则兜底
  判断，最终把请求分发到对应的模型组；决策日志记录每次判定的简单 / 复杂
  占比。我们照此实现，但做三处改动：① 向量层用确定性 n-gram 向量代替神经网络
  embedding（见下「诚实边界」）；② 模型组是模型名列表（与渠道解耦），组内第
  一个有合规渠道的模型服务，而不是 1Panel 的账号池直连；③ 某层无合规渠道时
  回落到另一层（仍在合规集合内），两层都无合规渠道时按分级路由的显式错误
  拒绝，而不是静默失败。
- **Performance Hub Model Router**（docs.performancehub.co，2026-11-23 查阅，
  旁证）：`auto` 同样是无定价的虚拟模型 ID，按提示复杂度在 Fast / Medium /
  Complex / Reasoning 四档中选模型、按解析出的模型计费；调用方只管发 `auto`，
  选路逻辑集中在网关侧。我们的两档（简单 / 复杂）是同一形态的简化版。

## 判定流程

```
model=auto
  → 分类：样本匹配（本地 n-gram 向量，阈值默认 0.35）
      未命中 → 规则兜底（长文本 / 多轮次 / 工具调用 → 复杂，否则简单）
  → 选组：按判定层级取模型组，组内按顺序找第一个有合规候选渠道的模型
      该层无合规渠道 → 回落到另一层（仍在合规集合内）
      两层都无 → 按分级路由显式错误拒绝（no_compliant_channel 等）
  → 转发：请求体里的 model 改写为解析出的具体模型，其余字段原样
```

判定在 DLP 扫描与数据分级之后、选路之前发生：被规则拦截的请求根本不会
走到路由；分类文本是请求原文（内容 + tool_calls 参数），分类本身只在本地
做样本匹配与规则判断，不调模型、不出站。

## 分类器

实现：`internal/autorouter`（`Classifier` + `Vectorize` 增强）。

- 向量化：复用 F28 的 `semreview.Vectorize`（字符 trigram + ASCII 词 unigram），
  再加一层字符 bigram——短中文问句的 trigram 太少（「今天星期几？」只有 3 个），
  插入一个字就会毁掉其中两个，bigram 对单字插入更稳健。F28 的向量化器本身
  未动，增强只在 autorouter 包内。
- 相似度：余弦相似度；另有一条「包含」分支——请求几乎原样包含某条样本
  （≥10 个共享 n-gram 且覆盖较小一方的 80%）时按包含度计分，避免长请求把
  嵌入的样本稀释到阈值之下；至少 3 个共享 n-gram 才算一次匹配（单个名词
  短语的巧合不是复杂度信号）。平局时倾向复杂——含糊的请求交给强模型比
  交给便宜模型更稳妥。
- 阈值默认 0.35（实测调参，见下）。
- 规则兜底（样本未命中时）：请求 ≥2000 字、消息 ≥6 轮、或带有 tool_calls
  时判复杂，否则判简单。规则是粗信号、是平局裁决，不是第二个分类器。
- 样本库：管理员在管理台维护（增 / 删），内置 12 条种子样本（简单 6、复杂 6，
  均为星河精密语境）。

### 阈值实测（调参依据）

种子库对改写与正常提示的实测相似度（`internal/autorouter` 分类测试）：

- 应命中的改写：0.39–0.56（如「帮我写一句新年祝福」0.50、「食堂今晚吃什么」
  0.39、复杂改写「对比两份采购合同的付款条件，指出风险并给谈判建议」0.56）。
- 不应命中的正常提示：最高 0.32（「本周的供应商报价单汇总」0.32，与复杂样本共
  享一个名词短语；「帮我写请假条」0.24）。
- 阈值 0.35 落在两者之间。重度缩写（如「星河精密几点上班」相对种子样本
  0.34）低于阈值——这是 n-gram 匹配的固有边界，规则兜底会把它判为简单，
  层级仍然正确；想覆盖这类缩写应补一条更短的样本，而不是调低阈值。

### 诚实边界

本轮的「向量」是确定性 n-gram 向量，**不是神经网络 embedding 模型**
（如 1Panel 用的 bge-m3）。单二进制 + 纯标准库的定位装不下一个 embedding
模型；`Vectorize` 是可替换的函数，接真实 embedding 后端时样本库、阈值与
决策日志不变。短主题词（如只发「供应商报价单」四个字）可能因共享名词短语
而匹配复杂样本——代价是一次强模型调用，不是错误答案；管理员可通过删改样本
收紧。

## 模型组

- 简单组默认 `["mock-eco"]`，复杂组默认 `["mock-pro"]`（演示 mock 模型：eco
  是便宜模型，pro 是强模型）。
- 组内顺序即选路优先级：第一个有合规候选渠道的模型服务。候选渠道的判定
  与直接请求完全相同（`pickCandidates`：数据密级上限 + 信任类型 + 冷却中
  排除 + 最低特权优先）。
- 组里写了一个尚无渠道提供的模型名时不报错（可能是待接入模型的前向引用），
  该模型只是永远解析不到；`GET /api/auto-route` 在 `unresolved_models` 里
  列出这类模型，管理台同步提示。

## 红线

- 复杂度路由只许在合规集合内做成本优化，绝不改变数据等级判定与渠道信任
  边界：机密请求在简单组模型（mock-eco，最高 internal）上无合规渠道时回
  落到复杂组（mock-pro，走脱敏云渠道）；绝密请求只能走本地模型渠道提供
  的模型。`resolveAutoModel` 的每一跳都复用 `pickCandidates` 的同一套过滤，
  不是另写一套。
- 分类不豁免任何安全层：语义复核（F28）照常在脱敏后文本上运行，例外凭证
  （F24）的豁免逻辑与直接请求同款（信任豁免时第二遍解析放宽信任过滤）。
- 关闭本层后 `model=auto` 返回 `model_not_available`，而不是静默落到某个
  默认模型——`auto` 不是任何渠道上的真实模型，静默回落会掩盖配置错误。
  `GET /v1/models` 只在启用时列出 `auto`。

## 接入点

网关 `ChatCompletions`：数据分级与自带级拦截之后、渠道解析之前。`auto`
请求解析出具体模型后，请求体里的 `model` 字段被改写（其余字段原样），
后续流程（脱敏、语义复核、缓存、转发、计费、审计）看到的都是解析后的模型
名；`detail` 里保留 `auto_route_requested=auto` 与判定字段，`model_call`
事件的 `Model` 字段是实际计费的模型。

## 审计与统计

- 每次 `auto` 调用在 `model_call` 事件的 `Detail` 里记录：`auto_route`
  （`层级:来源`，如 `simple:sample` / `complex:rule`）、`auto_route_confidence`
  （相似度或规则置信度 0.5）、`auto_route_requested=auto`、命中样本时
  `auto_route_sample`（样本 ID）、回落时 `auto_route_fallback`（实际服务的层级）。
  不含请求原文。
- 运行时计数（进程内，不持久化）：`auto` / `simple` / `complex` /
  `sample` / `rule` / `tier_fallback`，经 `GET /api/auto-route` 返回。
- 管理台「智能路由」页：策略表单（启用、阈值、两组模型）+ 计数 + 样本库增删，
  中英双语。

## 管理 API

- `GET /api/auto-route`：当前策略 + 样本库 + `unresolved_models` + 运行时计数。
- `POST /api/auto-route`：修改启用 / 阈值 / 两组模型（部分更新；两组同时为空
  且启用时 400）。
- `POST /api/auto-route/samples`：新增样本（`tier` 须为 simple/complex，文本
  4–2000 字）。
- `DELETE /api/auto-route/samples/{id}`：删除样本。

以上均仅 admin/security（roles.Policy），策略与样本变更记审计事件
（`auto_route_policy_updated` / `auto_route_sample_added|deleted`，只含
样本 ID 与层级，不含样本正文）。

## 已知限制

- 只有简单 / 复杂两档（1Panel 同款两档；Performance Hub 的四档在有更多模型
  时再评估）。
- 规则兜底只看长度 / 轮次 / 工具调用，不看代码特征——表面标记判断代码任务
  太嘈杂（引用代码不等于需要强模型，无代码的任务也可能很难），代码类请求
  靠样本库覆盖。
- 缓存（F11）按解析后的模型名与完整请求体做键：同一 `auto` 请求两次命中
  同一缓存条目；不同文本解析到不同模型时不共享缓存。
- 样本库为空时分类全部走规则：长文本 / 多轮 / 工具调用判复杂，其余判简单。
