# 首次开通与上线阶段（F34）

无专职 IT 的传统公司管理员 30 分钟内完成开通、第一天以观察模式跑起来。
本页讲开通流程本身；产品定位与弱点见 [README](../README.md)，三步上线的蓝图
依据见 [docs/blueprint.md](blueprint.md) §6.1。

## 首次设置码：创建第一个管理员

正式模式首次启动且没有任何用户时，服务器在日志里打印一条一次性设置码：

```text
first-run setup code: XXXX-XXXX-XXXX — open the web console and enter this code to create the first administrator
```

打开管理台即进入首次设置页（而不是登录页）：输入设置码、管理员用户名与密码
（≥ 8 位），即建成首个平台管理员，随后自动登录并打开开通向导。

- 设置码 12 位、60 位熵，只存 SHA-256 哈希，不存明文、不落盘；用过即废。
- 连续 5 次输错即作废，需重启服务器签发新码。
- 演示模式（`AGENTGATE_DEMO=1`）已种子出演示账号，不发设置码。
- 另一条路（dsh-ee 式）：`deploy/install.sh` 自动生成初始管理员密码并打印——
  本项目选了设置码一途，安装脚本不建管理员。

## 五步首次向导

管理台「开通向导」页（仅平台管理员 / 安全管理员可见），五步：

1. **创建管理员**——首个管理员已由设置码创建，本步只作确认；新增管理员
   去「用户与角色」页。
2. **选行业模板**——单选，见下。
3. **接模型渠道**——先选厂商（DeepSeek / 通义千问 / 智谱 / OpenAI / 自定义），
   Base URL、模型组、信任类型、最高等级由厂商预设预填并折叠进「高级」，只剩
   API Key 一个必填项；点「添加渠道」即建成。也可以「稍后添加」。
4. **选上线阶段**——三选一，默认观察模式，见下。
5. **自检与完成**——开通自检清单逐项变绿后，勾选「已备份主密钥」，点「完成开通」。

向导做完后仍可随时从导航重进：改模板、改阶段、重看自检。

## 保守模式预设与行业模板

模板 = 「保守模式」命名预设包 + 行业内容。应用模板时一次做齐：

- 上线阶段 = 观察；
- 脱敏：受管级与自带级双双强制脱敏（此前默认只脱敏受管级）；
- 报表节奏声明为每周（报表本身仍在「合规报表」页手动生成，暂无定时生成）；
- 绝密例外保持关闭（F24 开关默认关，预设不打开它）；
- 审计全开、留存 180 天（已是默认值，预设不改）；
- 模板词表并入网关自定义词（重启后从持久化记录重应用）。

首批两个模板（`GET /api/onboarding/templates`）：

| 模板 | 内容 |
|---|---|
| 通用保守 `general-conservative`（默认） | 不加行业词，只用内置 PII 与凭据检测；部门示例：行政 / 财务 / 业务 / 管理层 |
| 医疗器械 `medical-device` | 星河精密种子正式化：预置词表（注册证号、临床数据、设计输出、不良事件、XH-200、星河 XH-200，一律按机密管控）；部门：研发 / 注册 / 质量 / 生产 / 销售；文件夹密级映射建议：质量体系文件=内部、注册资料=机密、设计输出=机密 |

文件夹映射建议是指导文字，不自动建文件夹（文件夹只存在于客户的文件服务器上）。

## 上线阶段：观察 / 提醒 / 拦截

`GET / POST /api/onboarding/launch-phase`，仪表盘「开通进度」卡与向导第 4 步
均可切换，切换即时生效、无需重启，全程审计（`launch_phase_changed`，含上一阶段）。

| 阶段 | 网关行为 |
|---|---|
| 观察 `observe`（新装默认） | DryRun：只审计、不拦截、不脱敏；处置记为 `dry_run:*`，仪表盘可数「本应拦截 X 次」 |
| 提醒 `warn` | 自带级发机密数据的分级拦截改为提醒放行，处置记为 `warn`（附 `warn_reason=byoa_tier_would_block`）；其余规则照常拦截 |
| 拦截 `block`（已有安装的默认） | 全部规则按配置拦截 |

提醒阶段的边界（请当作产品承诺读）：

- **只放宽自带级分级规则这一条**。违禁词、语义复核仍拦截；「无合规通道」
  （例如绝密数据没有本地模型渠道）仍拦截——没有渠道可发，提醒也发不出去。
- 放行的数据仍只走信任合规的渠道：机密数据上签约云之前照常强制脱敏，
  绝密只走本地模型。提醒阶段改变的是「谁可以发」，不是「数据可以去哪」。
- 提醒是上线坡道，不是稳态。仪表盘「开通进度」卡常驻显示当前阶段与
  「本应拦截 / 已提醒」计数，看到数据平稳后一键进阶到拦截。

已有安装升级后阶段不变（此前行为即拦截），不会悄悄变成观察模式；
全新安装默认观察模式；演示模式固定拦截（PoC 需要演示拦截）。

## 开通自检清单

`GET /api/onboarding/checklist`（审计员也可看）。每一项都是实时测出来的，
不是存下来的宣称：

- 管理员已建：存在启用的平台管理员或安全管理员；
- 渠道已配置 / 渠道健康：存在已启用渠道 / 存在未冷却、未停用的渠道；
- 至少一台设备已接入：存在未吊销的接入令牌；
- 知识库已索引文件夹：已启用的文件夹源合计索引 ≥ 1 篇文档；
- 审计在写且哈希链完整：审计日志非空且链校验通过；
- 主密钥已备份确认：人工勾选（`POST /api/onboarding/ack`），机器无法代劳——
  主密钥丢失将导致全部加密密钥无法恢复；
- 当前上线阶段 + 观察期计数（本应拦截 / 已提醒）。

向导完成前，清单常驻仪表盘；向导完成后收起（`POST /api/onboarding/complete`，
幂等，保留首次完成时间）。
