# 文件夹即知识库（F18）

目标客户是传统/保守公司：没有现成的知识库系统，知识散落在共享文件夹的
Word / Excel / PDF 与老员工脑子里。设计原则是「零预置假设」——不要求客户
先整理录入，**指定共享文件夹即自动索引**，知识库从现有文件长出来。

## 注册与密级映射

管理员在管理台或 `POST /api/kb/folders` 注册一个文件夹：

| 字段 | 说明 |
| --- | --- |
| `name` | 显示名，如「公司制度」 |
| `path` | 服务器上的绝对路径（须为已存在的目录） |
| `level` | 该文件夹的密级（public / internal / confidential / secret），文件夹内所有文件继承此密级 |

密级映射即访问控制：机密文件夹的内容对自带级 Agent 完全不可见（目录、
检索、章节树、章节原文四处一致），受管级可见到机密；绝密文件夹内容两个
等级都不可见（与种子知识库的 `MaxLevelForTier` 规则一致）。

## 支持的格式（纯标准库，无新依赖）

| 格式 | 抽取方式 | 章节树 | 页码 |
| --- | --- | --- | --- |
| `.md` | 文本解析，`#`/`##`/`###` 为标题 | ATX 标题 | 45 行一页的伪页 |
| `.txt` | 文本解析 | 无标题时按页建节 | 45 行一页的伪页 |
| `.docx` | zip + XML（`word/document.xml`），只取 `w:t` 文本 | Heading1/2/3 段落样式；显式分页符分断 | 同上，分页符优先 |
| `.pdf` | 内容流抽取：Flate 解压后取 `Tj`/`TJ` 字面串 | 无（PDF 不可靠地提供标题） | 真实页码（内容流与页数 1:1 时）；否则伪页 |

PDF 抽取是 best-effort：扫描件（图片型 PDF）与自定义字体编码的 PDF
抽不到文本，此类文件会计入扫描统计的 `errors`，不静默索引空文档。
Excel（`.xlsx`）暂不支持——与 `.docx` 同属 zip+XML，后续轮次可按同一
模式接入；当前注册文件夹含 `.xlsx` 时会被跳过（不计入 scanned）。

## 索引树：PageIndex 式三层渐进式披露

借鉴 PageIndex（Vectify AI，见 backlog F18 借鉴点）：索引是一棵章节树，
而不是扁平分块；Agent 按三步取用，每步只拿当下需要的最小上下文：

1. **目录（Wiki 首页）**——`kb_catalog`：有哪些文档、属于哪个文件夹、
   什么密级、多少页、顶层章节标题。Agent 先看目录选文档。
2. **摘要页（章节树）**——`kb_structure`：某文档的节点树，每节点含标题、
   页码范围与摘要，**不含正文**。Agent 判断相关章节。
3. **原文下钻**——`kb_section`：某节点的全文，引用精确到
   `文件 + 章节 + 页码`（如 `考勤与请假制度.md / 请假流程 / 第 1 页`）。

`kb_search` 同样覆盖文件夹文档：按章节粒度命中，返回同样的文件 + 章节 +
页码引用，与种子知识库的命中合并排序、同一密级门禁。

### 摘要：抽取式，不经过模型

PageIndex 的节点摘要由便宜模型生成；我们改为**抽取式摘要**——取章节
自身的首句（无句界时取前 160 字）。这不是偷工减料，而是治理要求：
摘要生成本身不能成为泄漏通道（backlog 原要求）。抽取式摘要是原文的
子串，不调用任何模型、不出本机，且与原文服从同一密级门禁，因此摘要
不可能把机密内容带到不该去的地方。代价是摘要质量低于模型生成——
对制度类文档的首句通常就是主题句，可接受；后续如需模型摘要，必须
走分级路由/脱敏（机密以上先脱敏），另起轮次评估。

## 增量更新

每次扫描（启动时自动 + 管理员手动 `POST /api/kb/folders/{id}/rescan`）
只处理变化：

- 大小 + 修改时间未变的文件**不读文件**，直接记 `unchanged`；
- 时间变了但内容哈希（SHA-256）未变的，保留已解析文档，只刷新标记；
- 内容变了的重新抽取，记 `updated`；新增的记 `added`；删除的移出索引，记 `removed`；
- 抽取失败的记 `errors`，并保留该文件上一次的可用索引（不因一次损坏的
  写入丢掉可用的旧内容）。

扫描统计随 `GET /api/kb/folders` 返回，管理台的 Rescan 按钮可随时触发。

## 管理 API（仅 admin / security）

- `GET /api/kb/folders`：源列表 + 每源的文档数、最近扫描时间与统计、上一次错误。
- `POST /api/kb/folders`：`{name, path, level}`；路径不存在、密级非法 → 400；
  路径已注册 → 409。注册前先做一次完整扫描，扫不出内容不建源。
- `POST /api/kb/folders/{id}/rescan`：返回本次扫描统计与当前文档数。
- `DELETE /api/kb/folders/{id}`：删除注册并清空该源的内存索引。

创建、删除、重扫均写审计事件（只含文件夹名与统计数字，不含文件内容）。

## MCP 工具（Agent 侧）

- `kb_catalog`：目录（见上）。
- `kb_structure`：`{doc_id}` → 章节树。
- `kb_section`：`{doc_id, node_id}` → 章节全文 + 引用。
  `node_id` 为 `n0` 时取整篇文档（仅适用于短文档）。
- `kb_search`：种子知识库 + 文件夹文档合并检索，命中带 `source`
  （`kb` / `folder`）与 `section` / `pages` 字段。

工具结果同样过 DLP 扫描与自带级脱敏（与其他工具一致）。

## 演示

演示模式（`AGENTGATE_DEMO=1`）在仓库根目录运行时注册两个文件夹：

- `demo/folders/公司制度/`（internal）：`考勤与请假制度.md`；
- `demo/folders/机密资料/`（confidential）：`供应商准入要求.pdf`（2 页，
  内容流未压缩——有意保持纯 UTF-8 文本，见下）。

`make smoke` 对两者做端到端断言：检索命中、密级隔离、目录 → 结构 →
章节三步取用、重扫无变化。.docx 抽取由 `internal/folderkb` 的单元测试
覆盖（测试内现生成 .docx 夹具），演示文件夹里不放 .docx，原因是
**推送通道的限制**：整包快照推送（`push-files`）只接受 UTF-8 文本文件，
逐文件 contents API 会把 `content` 当文本再做一次 Base64，两种通道都
无法原样传输二进制文件；演示 PDF 因此特意用未压缩内容流（仍是合法的
2 页 PDF，抽取逻辑与压缩流同一条路，压缩流由单元测试覆盖）。

## 已知限制

- 伪页（45 行）不是渲染页码：`.md`/`.txt`/`.docx` 的引用页码是稳定的
  行窗口，不是 Word / PDF 的真实分页；只有 `.pdf` 用真实页码。
- `.docx` 只读正文段落，不读页眉页脚、批注、文本框与嵌入对象。
- PDF 抽取不支持扫描件、加密 PDF 与非标准编码；此类文件会计入 errors。
- 索引在内存中，重启后重新扫描（启动时自动扫）；超大文件夹的首次
  扫描时间与文件总大小成正比。
