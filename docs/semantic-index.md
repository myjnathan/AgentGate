# 知识库语义索引层（F19）

F18 的文件夹知识库给每份文档建了一棵章节树，每节点一段抽取式摘要
（章节首句）。摘要能定位章节，但讲不清「这节是干什么的、跟谁有关、
适用于谁、有什么硬约束」——Agent 判断相关性时只能靠标题猜。本层在
章节树之上加一层 **FRAS 语义条目**，作为目录层，替代弱摘要。

借鉴 AOCI-CODE（aoci-spec/aoci-code）的方法：每对象一行语义条目
（F 职责 / R 关联 / A 适用范围 / S 硬约束）+ 标签坐标 + 索引治理
（条目格式校验、漂移检测、覆盖率报告）。只借方法与思想，不复制代码：
AOCI-CODE 许可证为 FSL-1.1-MIT（Fair Source），与本项目 AGPL-3.0
不兼容；实现全部自研。

## 条目结构

每份文档的每个章节树节点（含根节点）一行条目：

| 字段 | 说明 |
| --- | --- |
| `function` | 职责：本节讲什么 |
| `relations` | 关联：与哪些章节 / 制度相关 |
| `applicability` | 适用范围：适用于谁 / 什么场景 |
| `constraints` | 硬约束：数字、期限、审批链、取用规则 |
| `tags.department` | 所属部门（文件夹配置的部门，未配时取文件夹名） |
| `tags.type` | 文档类型（抽取式按扩展名：Markdown / 纯文本 / Word / PDF；模型可返回更细的类型，如「制度」） |
| `tags.importance` | 重要度，由密级推导：公开 low、内部 medium、机密 high、绝密 critical |
| `source` | 原文回指：文件 + 章节 + 页码（如 `考勤与请假制度.md / 请假流程 / 1`） |
| `generated_by` | `extractive` / `model` / `mixed` / `title-only` |
| `generated_at` | 生成时间 |

**回指是强制的**：`source` 永远由索引树填入，不取模型文本。模型
即使在输出里编造了来源也会被丢弃——条目校验（`semidx.Validate`）
要求回指完整且页码格式为 `N` 或 `N-M`，且解析时只认树里真实存在
的 `node_id`。

## 两种生成方式

### 抽取式（默认）

不经过模型，从章节树与文件夹元数据直接生成，与 F18 摘要同一条
安全线：

- `function` = 章节标题 + 抽取式摘要；
- `relations` = 结构关系（上级章节 / 同级章节 / 包含章节）；
- `applicability` = 文件夹范围（文件夹名、部门、密级）；
- `constraints` = 该密级的取用规则（如「机密级：仅受管级可见，
  自带级不可见」）。

抽取式条目讲的是结构与范围，不是内容语义；内容级语义需要模型
生成。启动扫描与每次文件夹重扫后自动重新生成（只对新增 / 变化的
文档，内容哈希未变的跳过）。

### 模型生成（可选）

管理员在文件夹上点「生成语义索引」时传 `{"model": true}`，或在
服务端配好模型端点：

| 环境变量 | 说明 |
| --- | --- |
| `AGENTGATE_SEMANTIC_MODEL_URL` | 模型端点 base URL（chat-completions 兼容 API；通常就是本服务自己的网关地址） |
| `AGENTGATE_SEMANTIC_MODEL_TOKEN` | 调用网关的令牌（只存内存，不回显、不落盘） |
| `AGENTGATE_SEMANTIC_MODEL` | 模型名（默认 `mock-eco`） |

请求也可以在 body 里内联指定 `model_url` / `model_token` /
`model_name`（内联优先；令牌只用于当次请求，不存储、不记日志、
不返回）。

红线（代码里强制，不是约定）：

1. **提示词只含索引，不含正文**：发给模型的只有章节标题、页码
   范围与抽取式摘要，不发章节原文。模型从索引判断语义，正文始
   终留在文件夹里。
2. **请求走网关分级路由**：生成请求就是一次普通的
   `POST /v1/chat/completions` 调用，带
   `X-AgentGate-Data-Level: <文档密级>` 请求头，网关按该密级选
   渠道（F17：机密走脱敏云通道，绝密无合规通道时直接拦截）。
   模型输出再过一次条目校验，不合格的整篇文档回落抽取式。
3. **绝密文档永不送模型**：密级为 secret 的文档直接生成
   title-only 条目（只登记标题与章节名，不生成 FRAS 内容），
   无论是否要求模型生成；模型生成器本身也会拒绝 secret 快照。
4. **失败回落，不静默**：模型不可达、返回非 200、输出不是合法
   的条目 JSON 时，整篇文档回落抽取式，并在条目记录与 API 响应
   里记 `model_error`（只记状态码与解析失败原因，不记上游响应
   体原文）；模型只覆盖部分章节时其余章节抽取式补齐，
   `generated_by` 记 `mixed`。

## 索引治理

- **格式校验**：`semidx.Validate`——必填字段、四项 FRAS 各不超
  500 字、标签值合法（重要度只认 low/medium/high/critical）、
  回指完整。模型输出逐条校验，不过即整篇回落。
- **漂移检测**：条目记生成时的文档内容哈希；文件夹重扫后哈希变
  了而条目未重新生成时，覆盖率报告把该文档标为 stale。管理台语
  义索引卡片与 `GET /api/kb/semantic/coverage` 可见 stale 列表。
- **覆盖率报告**：已索引文档数 / 总文档数、已索引章节数 / 总章节
  数、stale 文档、已消失的文档（文件删了、条目还在时列为 missing，
  下次重扫自动清理）。

## 取用

Agent 的渐进式取用在 F18 三层之上多了一层（目录层）：

1. **目录**——`kb_catalog`：有哪些文档。
2. **语义条目**——`kb_entries`（新）：某文档每章节的 FRAS 条目，
   先判断相关性，再决定钻哪一节。同文档的密级门禁
   （`MaxLevelForTier`：自带级最高内部、受管级最高机密），机密
   文档的条目自带级不可见。
3. **章节树**——`kb_structure`：节点标题、页码与摘要。
4. **原文**——`kb_section`：某节点的全文，引用精确到文件 + 章节
   + 页码。

管理 API（均仅 admin/security）：

| 端点 | 说明 |
| --- | --- |
| `GET /api/kb/semantic/coverage` | 覆盖率与漂移报告 |
| `GET /api/kb/semantic/entries?doc_id=...` | 某文档的全部条目 |
| `POST /api/kb/folders/{id}/semantic` | 重新生成某文件夹的条目；body `{"model": true}` 走模型生成，可内联 `model_url` / `model_token` / `model_name` |

`POST /api/kb/folders/{id}/rescan` 与新建文件夹时自动刷新语义索引
（抽取式）；删除文件夹时其条目一并删除。

## 已知注意点

- 抽取式条目的 `relations` / `applicability` 是结构与范围信息，
  不是内容语义；要内容级 FRAS 需走模型生成。
- 模型生成是同步的：一个文件夹多篇文档时逐篇调模型，耗时随文档
  数线性增长；大批量生成建议分文件夹触发。
- 语义索引只在内存中，重启后启动扫描时重建（与 F18 文件夹索引
  一致）。
- 模型输出的 `tags.type` / `tags.department` 以模型返回为准，但
  须通过校验（非空、限长）；`importance` 须为四档之一，否则整篇
  回落抽取式。
