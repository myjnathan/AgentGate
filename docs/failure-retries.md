# 失败分类重试与尝试轨迹（F33）

网关转发上游失败时不再盲目重试：先按失败类别分类，再按类别处置。
借鉴 Bifrost 的 failure-classified retries
（docs.getbifrost.ai/features/retries-and-fallbacks），实现自研。

## 分类表

| 类别 | 触发条件 | 处置 |
|---|---|---|
| `auth` | 上游 401 / 403 | 立即轮换到下一把密钥（或下一同级渠道），**不重试同一密钥**、无退避；401 同时摘除该密钥（F12），403 不摘除（可能只是该密钥无此模型权限） |
| `transient` | 网络错误、429、5xx | **同一密钥**指数退避重试（基数 100ms，每次翻倍，上限 2s，+50% 以内抖动）；预算耗尽后转下一同级渠道 |
| `client` | 其余 4xx | 请求本身的问题，任何密钥/渠道都救不了——原样返回，不重试、不转移、不计熔断 |
| `success` | 2xx / 3xx | 正常返回 |

## 重试预算（分层预算）

- 每把密钥每次调用最多 3 次尝试（首次 + 2 次重试，`Policy.MaxTransientRetries`，默认 2）。
- 预算按密钥、按渠道分层：密钥轮换不消耗重试预算（Bifrost 同款规则——预算约束的是"可能恢复的密钥"，不是走到下一把密钥的路）；每个故障转移渠道获得一份全新的完整预算。
- 调用总尝试数上界 =（重试次数 + 1）× 密钥数 × 链上渠道数。

## 与 F1 / F12 / F17 的协同

- 熔断（F1）按**失败调用**计数，不按 wire 尝试计数：一个调用在某渠道上重试 3 次仍失败，只记 1 次连续失败；成功（哪怕是第 3 次尝试成功）照常清零。冷却语义仍是"N 次连续失败调用"。
- 密钥轮换（F12）不变：401 摘除密钥、同一请求换下一密钥继续；403 只轮换不摘除。
- 分级与信任（F17）不变：重试与故障转移只在首选渠道同一 `MaxDataLevel`、且信任合规的渠道集合内发生，绝不越级；机密/绝密的渠道约束高于可用性。

## 尝试轨迹（审计）

每次上游尝试写一条审计事件：Kind `channel`、Action `forward_attempt`，
Detail 只含元数据（不含请求/响应体、不含密钥原文）：

| 字段 | 含义 |
|---|---|
| `channel_id` / 事件 `Channel` | 渠道 |
| `key_masked` | 密钥指纹（脱敏显示值，如 `sk-…abcd`） |
| `attempt` | 本次调用内的尝试序号（从 1 起） |
| `class` | `auth` / `transient` / `client` / `success` |
| `status` | 上游 HTTP 状态码，或 `transport_error` |
| `duration_ms` | 该次尝试耗时（毫秒） |
| `result` | `served`（响应已返回给调用方）/ `failed`（该次尝试被丢弃） |

重试过的调用，其 `model_call` 事件 Detail 另带 `attempts`（总尝试数），
一眼可见重试成本。轨迹事件不进用量统计（只统计 `model_call` /
`violation`）、不触发告警。

## 与 Bifrost 的差异

- 429：Bifrost 轮换密钥（厂商常跨密钥共享账号级配额）；本项目按已批准的
  F33 规格在**同一密钥**上退避重试——本项目渠道按部署配置、密钥池本就
  是同一账号的，多密钥轮换烧掉的是同一配额。
- 全密钥鉴权失败：Bifrost 返回 502 `upstream_credentials_exhausted`；
  本项目返回最后一把密钥收到的上游鉴权响应本身（F12 惯例：调用方看到
  真实 401 / 403，例如"该密钥无此模型权限"）。

## 已知注意点

- 退避不读取上游的 `Retry-After` 头，只按指数退避；429 场景下若上游
  要求等待更久，重试可能再次撞限——后续轮次可评估按头等待。
- 403 可能是内容策略拦截而非密钥问题：按规格仍先走密钥轮换/渠道切换，
  全部失败后才把原始 403 返回给调用方；轮换过程不产生误摘除（403 不
  禁用密钥）。
- 流式调用只在收到响应头之前重试；一旦开始向调用方写 SSE，失败不再
  重试（与 F10 之前一致：已发出的字节无法收回）。
