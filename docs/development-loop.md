# 开发 Loop 协议（Development Loop）

AgentGate 由一个定时 Loop 持续推进开发（Nathan 于 2026-11-21 授权，全权执行）。
本文档是 Loop 每轮运行的固定规程，任何一轮都按此执行，保证**可持续、可审计、可回滚**。

## 节奏
- 每 2 小时一轮（Asia/Shanghai），每轮只做**一件事**：backlog 中优先级最高的一条，
  或修复一个已发现的问题。小步快跑，每轮必须留下可验证的成果。

## 每轮流程
1. **读状态**：读 `docs/feature-backlog.md`、`docs/DEVLOG.md` 最近条目、`git log` 最近提交，
   确认上一轮成果与本轮选题；先跑 `go test ./...` 确认基线绿色，基线红了先修基线。
2. **调研（如需要）**：选题涉及外部做法时，查 1–2 个一手来源（官方文档/源码/发布说明），
   把可借鉴点补记到 backlog 对应条目下（只记设计，不复制受 AGPL 等许可污染的代码）。
3. **实现**：最小完整切片——功能代码 + 单元/集成测试 + 必要的管理台/API 面。
   遵守既有约定：纯 Go 标准库优先；密钥只加密存储、绝不回显；审计不落敏感原文；
   数据分级约束高于可用性（如重试不得把数据送往更低密级渠道）。
4. **验证**：`gofmt`、`go vet ./...`、`go test ./...` 全绿；涉及端到端流程时补跑演示模式冒烟。
5. **记录**：更新 backlog 条目状态（doing→done 注明日期）；在 `docs/DEVLOG.md` 追加一条
   （日期、做了什么、关键决策、测试结果、提交哈希）；用户可见变化同步更新 README。
6. **提交与推送**：本地 `git commit`（信息格式 `feat/fix/test/docs(scope): 摘要`）；
   再把本轮变更的文件逐个用 GitHub 连接器的 `create_or_update_file` 同步到
   `myjnathan/AgentGate` main 分支（更新已有文件需带该文件当前远端 sha，先用
   `get_file_contents` 取得；注意：`push-files` 对非空仓库会报 403，不要用它做增量推送），
   并读回验证。**测试不绿绝不推送**；推送失败记录在 DEVLOG 并在下一轮优先处理。
7. **汇报**：向主对话发一条简短进展（做了什么、测试结果、下一轮计划）。
   失败或阻塞时说明原因与需要的协助；无实质进展不发空汇报。

## 红线
- 不改动项目定位与蓝图已定决策（不绑单一 Agent、分级信任、数据分级路由、PolyForm Noncommercial 许可证（禁止商用））。
- 不删除既有测试来"让测试通过"；发现 bug 先写复现测试再修。
- 不把任何真实密钥、客户数据写进仓库；演示数据只用虚构的「星河精密」。
- 单轮改动失控（测试反复不过、范围膨胀）时，回滚到本轮开始前的提交状态，
  在 DEVLOG 记明原因，下一轮拆小重试。
- 涉及对外发布、改仓库可见性、删数据等不可逆动作时，停下来等 Nathan 确认——
  Loop 的授权范围是**仓库内开发与推送**，不含对外发布动作。

## 停止条件
- backlog 中 P0/P1 全部 done 且蓝图 MVP 验收场景全过时，Loop 转为维护模式
  （每轮只做巡检 + 小修），并向 Nathan 汇报请求下一阶段目标。
- Nathan 随时可叫停或调整节奏。
