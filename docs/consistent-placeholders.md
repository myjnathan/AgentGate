# 一致占位符脱敏（F32）

脱敏把敏感值换成占位符（`<PII_1>`、`<CUSTOM_1>`）再发给模型，
响应回来再还原。占位符要想让模型看懂，必须满足一条：**同一个
敏感值，在一次请求里始终是同一个占位符**——模型才能指代
（「联系上面那个手机号」）。否则同一个号码出现两次、模型却
看到两个毫不相干的占位符，指代就断了。

借鉴 Kong AI PII Sanitizer 的占位符模式（Kong 官方插件文档
developer.konghq.com/plugins/ai-sanitizer，2026-11-23 查阅）：
placeholder 模式用 `PLACEHOLDER{i}`，**identical original values
receive the same placeholder**；`recover_redacted` 在响应中把
原文恢复回来（仅对输入脱敏生效）。我们只借占位符一致性这个
设计，Kong 该功能是企业版闭源插件、其检测走独立的 spaCy NLP
容器（`kong/ai-pii-service`，每语言一个镜像、需 600MB 以上内存），
两者都不复制、不采用；实现是本项目进程内规则检测 + 纯标准库，
与单二进制定位一致。

## 同一性是典范的，不是字面的

F10 已让完全相同的字符串共用一个占位符（一次请求一个
Redactor）。F32 把同一性从字面扩展到**逻辑值**：同一个值换种
写法出现，仍得同一个占位符——

| 写法 A | 写法 B | 占位符 |
| --- | --- | --- |
| `138-0000-0000` | `13800000000` | 同一个 `<PII_1>` |
| `Li@Xinghe.example` | `li@xinghe.example` | 同一个 `<PII_1>` |
| `6222 0000 0000 0000` | `6222000000000000` | 同一个 `<PII_1>` |
| `XH 200` | `XH-200` | 同一个 `<CUSTOM_1>` |
| `11010119900307123X` | `11010119900307123x` | 同一个 `<PII_1>` |

判定用 F29 的关键词归一化（`normalize.Keywords`：全角→半角、
统一小写、只留字母与数字）作典范键：PII 与企业自定义词按
归一化后的形式认同，凭据（API Key、令牌等）除外——密钥区分
大小写，只有完全相同的字符串才共用占位符。占位符名字仍带
类别（`<PII_n>`、`<CREDENTIAL_n>`、`<CUSTOM_n>`），编号按逻辑
值顺序编（同一个值出现两次不占两个号）。

## 恢复：返回首次出现的写法

一个逻辑值对应一个占位符，恢复时只能填回一种写法。规则是
**首次出现的写法为准**：请求里先出现 `138-0000-0000`、后出现
`13800000000`，模型回显的两个 `<PII_1>` 都恢复成
`138-0000-0000`。值本身完全相同，只是格式被统一成首次出现
的写法——这是为指代一致性付出的、可见且可预期的代价。

## 边界

- 映射只存在于单次请求的 Redactor 内存中，不落盘、不跨请求
  复用；多轮对话里同一值每轮重新编号（红线不变）。
- 占位符本身不携带原文信息（只有类别 + 序号）。
- 流式恢复（F10 的回填缓冲）行为不变：`MaxPlaceholderLength` 与
  `Restore` 未动，占位符被分片切断时仍经缓冲还原，不会半截泄漏。
- 适用位置：网关 `redactBody`（正文 + `tool_calls` 参数共用
  一个 Redactor）、MCP 工具结果与提示词渲染、sidecar 请求代理，
  三处共用同一套 `guard.Redactor`。
- 已知注意：F29 的关键词视图会把纯标点分隔的两个数字连成一串
  （如 `138-0000-0000，13800000000` 中间只有逗号），这时前一个
  变形值可能检测不到——占位符一致性只作用于已被检测到的值，
  检测本身的这个边界不在本条目范围内。
