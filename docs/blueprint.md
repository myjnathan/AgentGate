# 产品蓝图：不绑定 Agent 的企业 Agent 平台

> 状态：v0.1（讨论稿）
> 日期：2026-11-21
> 关联文档：《企业级防护方案设计》（enterprise-protection-design.md）——防护体系细节以该文档为准，本文引用其结论。
> 参考项目：hikariming/dsh-ee（绑定 DSH 的同类平台，Apache-2.0）、QuantumNous/new-api（模型网关）、Calcium-Ion/AstrLink（本地隐私网关）

---

## 0. 可行性结论

**可行。** 判断依据：

1. **没有未解的科研问题，全部是工程整合问题。** 本产品需要的每一块能力都有已跑通的先例：
   - 企业治理闭环（接入→组装→审核→授权→下发→审计）——dsh-ee 已验证；
   - Go 实现的模型网关（多上游、配额、审计、防护管线）——New API 已验证，且同为 Go；
   - 端侧本地隐私网关（本地检测、可逆脱敏、响应还原）——AstrLink 已验证；
   - 跨 Agent 的标准接口——MCP 与 OpenAI 兼容协议已是各桌面 Agent 的公共约定。
2. **差异化是架构级的，不靠功能堆量。** “不绑 Agent + 分级信任 + 预防型防护”在第一天定架构即可成立，后发者（包括原版和厂商企业版）受既有架构所限难以跟进。
3. **主要风险不在核心技术，在范围与适配**（见第 12 节）：各 Agent 的协议支持程度参差、跨平台端侧控制差异、透明加密厂商的白名单粒度差异。应对方式是先做技术探针（第 13 节）再全量开发，以及严守 MVP 范围。

粗略工作量估计（单人全职、仅供排期参考，非承诺）：技术探针约 2 周；MVP 闭环约 6–10 周；达到可给第一家企业试点水平约再 6–8 周。

## 1. 产品定义

### 1.1 一句话定位

**员工的 Agent 随便换，企业的能力、权限和账本不动。**

一个开源、自托管、不绑定任何单一桌面 Agent 的企业平台：企业把系统、知识、模型和能力沉淀在平台侧，员工用自己习惯的通用桌面 Agent（DSH、WorkBuddy、Claude Code、Codex 等）经标准协议接入；涉及企业加密文件时，只有通过准入的受管 Agent 能在预防型防护下工作。

### 1.2 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 企业 Agent 的治理与交付层（控制面） | 不是 Agent 运行时，不做推理、不做对话 UI |
| 模型网关 + MCP 网关 + 能力中枢 + 审计中心 | 不是某个 Agent 的插件或附属品 |
| 端侧防护组件的提供方（本地隐私网关、出口守卫、受管包） | 不做终端安全软件（杀毒/EDR），与企业已有终端安全共存 |
| 开源、中立、自托管 | 不做托管 SaaS，不经手客户数据 |

### 1.3 目标客户（按优先级）

1. **主力**：50–2000 人、已部署透明加密/DLP 的中国企业（制造、医疗器械、研发型企业为典型），员工已在自发使用各类桌面 Agent，IT/安全部门面临“禁不住、又管不了”的局面。
2. **次级**：没有加密体系但需要统一模型配额、能力分发与审计的中小企业（轻部署模式切入）。
3. **不做（早期）**：强监管金融/政务的大型集采（周期长、资质门槛高，留待合规期后）。

### 1.4 角色

- **平台管理员**（IT）：组织、身份、网关策略、Agent 分级与准入、系统设置
- **安全管理员**：防护策略、DLP 类目、审计与违规处置、加密文件通道审批（三权分立可选，MVP 先与平台管理员合并，保留角色位）
- **能力运营者**（业务骨干）：发布技能/专家/微应用、知识维护，提交审核
- **审核人**：能力上架、敏感能力授权审批
- **员工**：用自己的 Agent 接入，只需一次登录

## 2. 设计原则

1. **协议优先，不绑客户端**：平台只对外提供标准协议（OpenAI 兼容、远程 MCP、OIDC、SKILL.md 分发）。对具体 Agent 的适配只允许存在于“薄适配层”（配置写入脚本），且任何适配失效都不能伤及平台主体。
2. **预防优于审计**：能事前拦的绝不只事后查。审计的定位是第二道防线与合规证据，不是主要卖点话术（与 SaaS 型 Agent 拉开差距的核心）。
3. **分级信任，而非一刀切**：Agent 分受管级/自带级，数据分公开/内部/机密/绝密，两维交叉决定权限与模型去向（见第 6 节）。
4. **网关是唯一咽喉**：模型调用、工具调用、知识检索必须过平台网关；端侧组件只做第一道闸与出口收窄，不单独成为控制点。
5. **轻部署**：单二进制 + 嵌入式 Web UI；SQLite 起步、PostgreSQL/MySQL 可选；支持完全离线部署；提供 5 分钟 PoC 模式（内置模拟公司数据，一键体验全闭环）。
6. **开源即可审计**：企业治理功能全量开源（不学 LiteLLM 的企业版闭源切分），信任来自代码；商业化靠实施、支持与行业包（见第 11 节）。
7. **默认安全**：原文日志默认关、密钥加密存储、敏感配置不回显等基线从第一版做起，不留“以后再补”的安全债。

## 4. 核心子系统

### 4.1 身份与组织
- 本地账号 + OIDC + LDAP/AD；SCIM 或定时同步组织架构（部门/岗位）
- RBAC：平台角色（第 1.4 节）× 能力可见范围（部门/角色/个人）
- 设备码登录（员工在 Agent 侧发起，浏览器确认），签发**分级令牌**：令牌内嵌员工、设备、Agent 类型与等级、有效期；短时令牌 + 刷新机制，可即时吊销
- 登录安全：限流、账号级失败锁定、敏感操作 step-up 验证

### 4.2 能力中枢
- 资产类型：技能（SKILL.md 包）、专家/专家团（人设+技能组合）、提示词模板、微应用（人设+工作台+素材，二期）
- 生命周期：草稿 → 静态扫描（风险文件/依赖/密钥）→ 沙箱行为检测（二期）→ 人工审核 → 签名发布 → 按范围下发 → 版本更新需复审 → 下架全员失效
- 分发方式（不绑 Agent 的关键）：同一资产多形态输出——MCP 工具、技能包下载/订阅目录、提示词注入端点，由各 Agent 按自身能力消费
- 企业 scope 永不回落公共源，防依赖混淆；npm/包注册表代理为二期

### 4.3 模型网关 + 防护管线（核心）
- OpenAI 兼容 `/v1`（含 Responses/Claude Messages 协议适配按需），多上游渠道、加权/健康分路由、失败重试与熔断、按账号月度 token 配额与可用模型清单
- 防护管线（插件化、可按部门/模型/Agent 等级生效、可试运行、变更入审计）：
  鉴权 → 限流配额 → 敏感词过滤 → DLP 检测（凭据/PII/企业自定义类目）→ 提示词注入检测 → **数据分级判定与路由** → 脱敏/令牌化 → 路由转发 → 响应侧检测（默认关，高密级开）→ 审计落盘
- 数据分级路由表见《企业级防护方案设计》第 2 节；处置动作统一为：放行 / 告警 / 脱敏 / 拦截 / 人工审批
- 上游密钥经主密钥加密存储（可选对接 KMS/Vault），管理接口不回显

### 4.4 MCP 网关
- 企业系统以 MCP 或 OpenAPI 接入，统一转远程 MCP 对外；**工具级授权**（部门/角色/Agent 等级 × 单个工具）
- 系统凭据只存服务端、按调用注入，永不下发员工机
- 工具入参/返回双向过 DLP（返回是敏感数据进模型的第二入口）；每次调用全量审计

### 4.5 知识与数据中枢
- 知识库：文档（PDF/Word/Markdown）版本管理与回滚；检索走“关键词多轮检索 + 读原文 + 带引用回答”（沿用原版已验证的无向量库路线，部署更轻）；检索接口以 MCP 工具形态提供，任何 Agent 可用
- 无现成知识库的客户：指定共享文件夹即自动索引（文件夹即知识库，F18；PageIndex 式三层渐进披露：全局目录/Wiki 首页 → 文档摘要页与章节页码索引树 → 原文按需下钻，引用精确到文件+章节+页码；摘要生成本身也走分级路由/脱敏）。
- 数据中枢（二期）：共享数据集只读账号查询，支持 `:me_department` 等按人参数，行级范围由服务端注入，员工/Agent 不可越权拼接

### 4.6 端侧组件
- **接入工具（setup）**：一条命令完成登录与配置——自动检测本机已装 Agent，为每个 Agent 写入模型网关地址、MCP 配置与令牌；同时支持手工配置文档（协议公开，不依赖工具）
- **本地隐私网关 sidecar**：见《防护设计》第 0 层；规则 + 本地小模型检测、可逆脱敏（占位符映射只存本机）、响应还原、原文捕获默认关
- **受管 Agent 包**：基于 DSH 的企业构建——锁定版本与配置、自编译签名分发、禁用自加外部 MCP/插件白名单、工作目录沙箱、高危命令确认、改动备份与整轮回滚
- **进程级出口守卫**：随受管包下发的系统防火墙规则模板（Windows/macOS/Linux），受管进程只准连企业网关与本机 sidecar；规则与进程哈希定期上报平台校验（Agent 证明）

### 4.7 审计与运营台
- 审计字段与冷热归档、防篡改、违规全链、异常告警见《防护设计》第 4 层
- 运营视图：用量/成本（人/部门/模型/能力）、防护命中与误报率、Agent 分布与版本、能力使用排行
- 策略管理 UI 必须支持**试运行模式**与命中样本回看（降低企业上线防护策略的心理门槛）

## 5. 协议与接入规范（对外契约）

| 接口 | 用途 | 说明 |
|---|---|---|
| `POST /v1/chat/completions` 等 | 模型调用 | OpenAI 兼容；请求头携带分级令牌 |
| `POST /mcp`（远程 MCP，Streamable HTTP） | 工具/知识/数据调用 | OAuth/令牌鉴权，工具级授权在服务端执行 |
| `/api/setup/*` | 设备码登录、令牌签发/刷新/吊销 | 供 setup 工具与 Agent 适配使用 |
| `/api/capabilities/*` | 能力目录、技能包下载、版本订阅 | 按令牌范围过滤 |
| `/api/attestation` | Agent 证明上报 | 版本/配置哈希/插件清单/守卫规则状态 |
| 管理 API `/api/admin/*` | 运营台 | 与员工侧令牌体系隔离 |

**Agent 适配分级**（适配是可替换的薄层，平台契约不为任何 Agent 定制）：
- **L3 受管适配**：受管 Agent 包（首个：DSH），全功能 + 白名单资格
- **L1 配置适配**：setup 工具自动写配置（目标：DSH、Claude Code、Codex、Cursor，按探针结果排序）
- **L0 协议接入**：任何支持自定义模型地址或远程 MCP 的 Agent 手工接入（WorkBuddy 走此级：可用其 MCP 连接器与自定义模型能力接通用能力，定位自带级）

> 兼容性矩阵（各 Agent 对远程 MCP 鉴权、自定义模型、技能目录的支持实测）是探针阶段的交付物，蓝图不在此处凭印象下结论。

## 6. 分级信任模型（摘要，详见《防护设计》2.1）

- **Agent 等级**：受管级（过准入标准 7 条 + Agent 证明持续校验）/ 自带级（登记即可用通用能力）/ 未登记（无企业能力）
- **数据密级**：公开 / 内部 / 机密 / 绝密
- 交叉规则示例：加密文件明文仅受管级可读；机密数据默认走网关脱敏后上云（原文不出公司），绝密无合规通道时直接拦截并提示；私有模型只是可选项之一；自带级 Agent 的模型流量强制过网关 DLP 且禁访机密以上能力
- 准入标准与出口守卫为产品**硬规则**（内置评估清单 + 部署检查），不是文档建议

---

## 6.1 目标客户与落地方式

> **目标客户是传统、保守的公司——零预置假设**：不假设客户有自有模型、数据库、知识库中的任何一样。知识散落在共享文件夹的 Word/Excel/PDF 与老员工脑子里。
>
> **默认保守模式**：机密以上默认拦截、审计全开，开箱即用，不依赖配置能力。
>
> **上线分三步**：先观察（DryRun，只审计不拦截）→ 再提醒 → 后拦截。先保证不出事，再谈提效。
>
> **双轨可插拔**：下限保底（文件夹知识库、脱敏上云、单二进制，零依赖能跑）+ 上限开放（已有知识库、MCP 服务经 F6 MCP 联邦、F7 REST 适配接入）。治理层（分级/脱敏/审计）不变，能力源可插拔。

## 7. 核心数据模型（实体清单）

组织：`org_unit`（部门树）、`user`、`role`、`user_role`
设备与 Agent：`device`、`agent_install`（类型/版本/等级/证明状态）、`token`（分级令牌、吊销表）
能力：`capability`（技能/专家/模板/微应用）、`capability_version`（含签名与扫描结果）、`review`（审核单）、`grant`（可见/可用范围）
网关：`channel`（上游渠道，密钥密文）、`model_policy`（可用模型/配额）、`protection_policy`（管线策略与版本）、`dlp_category`（类目与规则）
调用与审计：`call_log`（模型调用）、`tool_call_log`（MCP 调用）、`audit_event`（管理与安全事件）、`violation_event`（防护命中全链）
知识与数据：`kb_document` / `kb_version`、`dataset` / `dataset_grant`
归档：`log_archive`（冷存索引）

## 8. 技术选型与仓库结构

- **服务端**：Go（单二进制、Web UI 静态嵌入、单端口多路由：`/`、`/api`、`/v1`、`/mcp`）
  - 路由/中间件：标准库 + 轻量路由（chi 或同类），管线以中间件链实现
  - 数据访问：sqlc 或 sqlx 风格，显式 SQL，避免重 ORM；迁移内置版本化
  - 数据库：SQLite（默认，modernc 纯 Go 驱动保单二进制）/ PostgreSQL / MySQL 三档
- **端侧**：setup 工具与 sidecar 均 Go 实现（与服务端同仓，交叉编译三平台）；出口守卫以规则模板 + 安装脚本交付，不常驻特权进程
- **前端**：React + Vite + Tailwind（与原版同栈，便于借鉴与招募贡献者），中英双语
- **仓库结构（monorepo）**：
```text
server/        平台服务端（internal: identity, capability, gateway, guard, mcp, kb, audit, store...）
web/           管理与员工 Web UI
endpoint/      setup 工具、本地隐私网关 sidecar、出口守卫模板
managed-agent/ 受管 Agent 构建脚本与锁定配置（基于 DSH 上游）
deploy/        Docker / 裸机 / 离线包脚本
docs/          部署、接入、防护白皮书、准入评估清单
e2e/           关键闭环端到端测试
```

## 9. MVP 范围与验收闭环

### 9.1 MVP 必做（P0）
身份与组织（本地账号+OIDC、部门 RBAC、设备码登录、分级令牌两级）· 能力中枢最小版（技能包 CRUD/版本/范围/审核/签名）· 模型网关（多渠道、配额、可用模型清单）· 防护管线（敏感词 + 规则级 DLP + 按通道信任类型分级的路由 + 拦截/脱敏）· MCP 网关（OpenAPI 转 MCP、工具级授权、凭据托管、调用审计）· 知识库（关键词检索 MCP 工具）· 审计检索与导出 · setup 工具（DSH + 至少一款其他 Agent 的配置适配）· 策略试运行模式 · PoC 模拟公司模式

### 9.2 明确不做（MVP）
微应用、专家团编排、数据中枢、包注册表代理、本地小模型检测（sidecar 先只做规则检测）、沙箱行为检测、SIEM 对接、行业包

### 9.3 验收演示场景（MVP 完成定义）
> 模拟公司“星河精密”（医疗器械，120 人）一键生成。研发员工小李：
> 1. 在自己装的 Claude Code 上跑 setup，30 秒完成接入（自带级）；问公司报销政策（知识库带引用回答），调用打卡 MCP 工具成功；尝试让模型处理一份标密的客户名单，网关 DLP 命中，脱敏后路由到签约模型并留痕。
> 2. 换到公司下发的受管 DSH（受管级），打开透明加密的注册文档（白名单进程读明文），让 Agent 摘要并写入内网注册系统（MCP 写操作经审批策略）；同一文件内容若试图发往公网模型，被分级路由拦截并产生违规事件，安全管理员在运营台看到全链并收到告警。
> 3. 安全管理员把一条新 DLP 规则以试运行模式上线一周，查看误报样本后转正式。
> 全程：管理台可见每一次调用的人、设备、Agent、密级、策略命中与成本。

## 12. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 各 Agent 协议支持参差（远程 MCP 鉴权方式、技能格式差异） | “随意接入”体验打折 | 探针先行；适配分级（L0–L3）如实标注；平台契约只依赖最普及的协议子集 |
| WorkBuddy 等 SaaS Agent 不开放模型地址/配置 | 其用户只能 L0 接 MCP 通用能力 | 定位上接受：它本就只应处理低密级；把限制写进准入清单而非硬凑适配 |
| 端侧跨平台差异（尤其 macOS 进程级防火墙能力弱） | 出口守卫强度不一致 | 按平台分级实现并如实标注强度；macOS 以 sidecar 强制 + 网络扩展为远期 |
| 透明加密厂商白名单粒度/兼容差异 | 受管通道在某些客户落不了地 | 探针期选 1–2 家主流厂商实测；输出兼容清单；必要时与厂商做联合验证 |
| DLP 误报/漏报 | 误报伤体验，漏报伤信任 | 试运行模式为默认上线路径；规则+模型分级；命中样本回看与白名单工作流 |
| 流式响应 DLP 的延迟 | 高密级场景体验差 | 默认只扫请求侧；响应侧扫描按部门可选并明示代价 |
| 跟随 DSH 上游维护受管构建 | 持续成本 | 受管包只做配置锁定与构建脚本，不 fork 内核；版本节奏跟随上游稳定版 |
| 范围膨胀（学原版全功能表） | MVP 烂尾 | 以 9.3 验收场景为唯一完成定义，新增需求一律进 P2 以后 |
