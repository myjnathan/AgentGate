# 与 IP-guard 配合指南（透明加密集成）

目标读者：已部署（或计划部署）溢信 IP-guard 的企业 IT/安全管理员、AgentGate 实施方。
同类产品（天锐绿盾、亿赛通等）机制相同，本文方法通用；IP-guard 是我们的**首个实测适配对象**（探针 5）。

## 1. IP-guard 的机制（配合点从哪来）

据公开资料（溢信官网/产品型录/经销商方案，2026-11 查阅）：

- **驱动层透明加密**：文件落盘即密文；加解密在文件系统驱动层完成，对用户无感。
- **按"授权软件（涉密进程）"授权**：加密策略可按**应用程序**、扩展名、文件夹、内容关键字定义。
  被授权的进程读写文件时自动解密/加密；**未授权进程读到的永远是密文**。
  官方明确支持把"客户自行开发的软件"加入授权软件——这是受管 Agent 的准入通道。
- **配套管控**：外发解密审批（申请人→管理员/代理管理员审核→生成外发文件）、外发阅读器、
  U 盘白名单、打印水印、网页/网盘/邮件/IM 外发管控、全量行为审计；支持 AD/LDAP 同步与
  Windows/macOS/Linux/信创终端。
- **没有公开的第三方 API/SDK**（截至查阅时）：因此配合方式是**策略配置 + 进程准入**，
  不是代码级集成。任何声称能"API 对接 IP-guard"的说法都应要求厂商书面确认。

## 2. 配合架构：三道闸各管一段

```text
[IP-guard]  文件在磁盘上：只有授权进程能见明文 ──┐
[受管 Agent] 读明文 → 进程级出口守卫：只准连企业网关 ┼→ 明文不出终端
[AgentGate] 网关侧：数据分级路由/脱敏/审计 ────────┘
```

分工原则：
- **文件级外发**（拷 U 盘、发邮件、传网盘）继续走 IP-guard 既有管控与解密审批，AgentGate 不重复造轮子；
- **语义级外发**（把明文内容发给模型）是 IP-guard 管不到的新通道，由 AgentGate 的
  数据分级路由 + 脱敏 + 审计补位；受管 Agent 的进程级出口守卫保证它连不上网关以外的地址；
- **审计双轨**：IP-guard 记终端行为（谁、何时、哪个文件），AgentGate 记语义行为
  （哪段内容、什么密级、发给了哪个模型、什么处置），企业 SIEM 可按人/时间汇聚对账。

## 3. 企业 IT 配置清单（在 IP-guard 控制台）

1. **登记授权软件**：把受管 Agent 加入"应用程序"清单。登记材料由 AgentGate 实施方提供
   （见 §5 申请材料包）：进程名、安装路径、发行者签名证书指纹、版本与升级节奏。
2. **绑定加密策略**：对目标安全区/部门，将受管 Agent 设为可读写加密文件的授权软件；
   策略粒度建议按部门试点（先一个部门、一个文档库），验证无误再扩围。
3. **子进程清单（关键）**：Agent 工作时会拉起子进程（Shell、脚本运行时、外部工具）。
   凡是需要直接读加密文件的子进程，必须一并加入授权清单（我们提供《受管进程树清单》）；
   未登记的子进程读到密文是**预期行为**，不是故障。
4. **剪贴板/截屏/打印**：保持 IP-guard 既有策略不变，受管 Agent 不申请豁免；
   如业务确需放开，按部门单独评估并留审计。
5. **网络管控叠加（可选双保险）**：如 IP-guard 的网络控制策略支持按进程限制，
   给受管 Agent 再加一条"仅允许访问企业网关地址"，与我们进程级出口守卫双保险。

## 4. 验证矩阵（上线前逐项实测，对应探针 5）

| # | 用例 | 期望结果 |
|---|---|---|
| 1 | 受管 Agent 读取加密文档 | 得到明文，可正常问答/编辑 |
| 2 | 员工自带 Agent（WorkBuddy 等未授权进程）读同一文档 | 密文/乱码，无法使用 |
| 3 | 受管 Agent 编辑并保存文档 | 落盘仍为密文（涉密进程产出自动加密） |
| 4 | 未登记子进程（如临时脚本）读文档 | 密文；登记后恢复明文 |
| 5 | 受管 Agent 试图把机密内容发往公网模型 | 被 AgentGate 分级路由拦截/改道私有模型并告警 |
| 6 | 受管 Agent 进程直连公网（绕过网关） | 被出口守卫拒绝 |
| 7 | 拷贝加密文档到 U 盘/网盘 | 走 IP-guard 管控：拦截或触发解密审批，AgentGate 不干预 |
| 8 | 双轨审计对账 | 同一事件在 IP-guard 与 AgentGate 审计中可按人/时间对应上 |

## 5. AgentGate 提供的申请材料包（managed-agent/ 随受管包交付）

- 受管 Agent 进程清单（主进程 + 受控子进程树）与各自职责
- 发行签名证书指纹、版本清单、升级节奏与回滚方式说明
- 出口守卫规则说明（进程只连企业网关 + 本机 sidecar）
- 本指南的验证矩阵签字页（试点验收用）

## 6. 已知边界（如实说明）

- IP-guard 策略按**进程**授权，不区分"同一进程内的不同数据用途"——进程内的
  语义管控（分级/脱敏/审计）由 AgentGate 承担，这正是两道闸要叠加的原因。
- macOS/Linux 上 IP-guard 的功能完整度与 Windows 有差异，试点前按官方兼容表逐项确认；
  出口守卫在 macOS 的强度限制见 `endpoint/egress/README.md`。
- 版本升级：受管 Agent 升级若更换签名或进程结构，需提前向企业 IT 报备并复核授权清单，
  避免升级即失效；我们的发布节奏为此保持签名证书长期稳定。
