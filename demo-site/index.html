守的不是 Agent，是三道门

任何 Agent 想在公司里真正干活，都必须过这三关。门在我们手里，Agent 随便换。

模型门

统一的模型网关：数据先分级再放行——公开、内部走签约云；机密先脱敏再上云，原文不出公司；绝密只走本地模型或直接拦截。配额、成本、审计全在这里。

能力门

公司的知识库和业务系统只以受授权的 MCP 工具形式开放，凭据永远留在网关一侧、不下发到员工电脑。员工能查到什么，由他的密级决定，不是由他用的工具决定。

终端门

受管 Agent 上岗先「证明」自己：版本、配置、插件清单对不上策略，自动降级。员工电脑上的守护程序在数据离开机器之前就先脱敏，明文不出端。

核心能力

为没有自有模型、没有数据库、没有知识库的传统公司设计：零预置假设，开箱即用。

分级路由

按数据密级和通道信任类型自动选路：签约云、专有云、本地小模型各行其道，无合规通道时明确拦截并说明原因。

可逆脱敏

身份证、手机号、密钥等敏感信息出门前替换为占位符，响应回来自动还原，连流式输出也不漏。映射只在内存中，用完即毁。

文件夹即知识库

把共享文件夹指给它，自动建成带目录、摘要和页码引用的 Wiki 知识库。知识从现有文件里长出来，不用先整理录入。

专题知识包

围绕具体工作问题精选文件、写综合说明，结论条条带原文出处。口径受控、责任可追溯的「案卷」，不是大杂烩。

Agent 证明与终端盘点

受管 Agent 登录时提交版本与配置证据，平台核验后才发受管令牌；终端持续心跳盘点，配置漂移一眼可见。

例外审批

被拦下的高密级调用可以申请例外：员工说明理由，管理员审批，一次性放行，全程留痕。绝密默认不可例外。

防篡改审计

审计日志带哈希链，事后改一条就会断链。谁在什么时候把什么级别的数据发给了哪个模型，清清楚楚。

组织同步

钉钉、飞书、企业微信的部门和员工目录自动同步，第三方身份登录时绑定。同步只建账号，不自动给权限。

与透明加密配合

和 IP-guard 等透明加密产品分工：文件级外发走加密产品的审批，语义级外发走 AgentGate 的分级。为受控 Agent 开进程白名单读明文，出口由我们守住。

部署：一个文件，三步

单二进制 + 自带存储，不要求数据库、不要求容器、不要求云。对比同类产品动辄 TiDB/OceanBase 起步，这是给中小公司准备的形态。

第一步

下载对应平台的二进制，放到任意一台内网机器（Windows / Linux / macOS 均可）。

第二步

设一个主密钥启动，打开管理台，按「保守模式」预设确认策略——机密以上默认拦截、审计全开。

第三步

员工用设备码接入自己的 Agent。先开「观察模式」只审计不拦截，跑两周看报表，再逐步收紧。

弱点明说

我们把防护边界写在明处。做不到的，不假装做得到。

  • 只防电脑里的数据流。员工拍照、默记、口述把信息带出去，不在任何软件的防护范围内——那是贵公司保密制度的事，我们明说，不遮掩。
  • 规则检测看字面，不看语义。把机密换个说法、拆开、编码再发，规则可能抓不住（语义复核层已在开发路线图上）。目前靠审计抽查和异常告警兜底。
  • Agent 证明是软件自报。能防配置错误和私自改装，防不住蓄意伪造证据的高手——这一层定位是「证明题」不是「防弹衣」。
  • 签约云的「零留存」是合同承诺，不是技术保证。所以我们的默认做法是先脱敏再上云：云端看到的是占位符，承诺落空也拿不到原文。
  • 单机版没有高可用。网关宕机时受管调用会中断（高密级默认拦截，不会 fail-open 放行）。双机热备在路线图末尾。

开源与许可证

AgentGate 采用 GNU AGPL-3.0 开源：任何人可以免费使用，包括商业使用；但如果你修改了它并对外分发、或用它提供网络服务，就必须同样以 AGPL 开源。我们图的是让大家用起来，同时防止大厂闭源拿去转卖。代码是否可信，不用听我们说——自己审计，或者让你的集成商审计。
